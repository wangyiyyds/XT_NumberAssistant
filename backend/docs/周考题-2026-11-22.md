### 题目 1：统一响应外壳 + Repository 层封装（20 分）

**背景（对应本周 commit `06c1c95`、`74336a7`）：**
本周项目把所有 Controller 的返回值包了一层统一外壳，并新增了 Repository 层隔离数据访问。

**任务：**
1. 新建一个实体 `Notice`（公告），字段至少包含：`id`、`publicId`、`title`、`content`、`createdAt`。
2. 仿照 `UserRepository` / `UserRepositoryImpl` 的写法，为 `Notice` 编写：
   - Repository 接口：`findByPublicId`、`existsByTitle`、`listTop10`（按 createdAt 倒序）
   - 实现类：使用 MyBatis-Plus 的 `QueryWrapper` 完成查询，继承 `CrudRepository`
3. 编写 `NoticeController`，提供以下接口，**所有返回值必须使用 `Result<T>` 外壳**：
   - `POST /notices` 新建公告（返回 200 + 新建结果）
   - `GET /notices/{publicId}` 查询公告（查不到返回 **404**，body 为 `Result.fail(404, "...")`）
   - `GET /notices` 返回最近 10 条
4. 异常路径必须走 `GlobalExceptionHandler`，不允许在 Controller 里 try-catch 吞异常。

### 题目 2：Spring AI 集成 —— 带人设与历史窗口的流式 AI 服务（25 分）

**背景（对应本周 commit `41089d4`、`6876c92`）：**
本周项目用 Spring AI 的 `ChatClient` 接入 DeepSeek，实现了「人设 system prompt + 最近 N 轮历史 + 流式输出」的对话能力。

**任务：**
1. 完成 Spring AI 依赖引入与 `application.yml` 配置（api-key 走环境变量，禁止硬编码；代码里给出 `OPENAI_API_KEY` 或自定义占位符即可，不必真实调用）。
2. 编写你自己的 `AiService` 实现 `MyAiServiceImpl`，要求：
   - 实现 `Flux<String> streamReply(Agent agent, String userText, List<Message> history)` 签名
   - 人设：`agent.getInstructions()` 有值则作为 system prompt；否则用兜底文案
   - **历史窗口裁剪**：只取按 id 升序排序后的最近 10 条历史（参考 `HISTORY_WINDOW` 的做法，用 `skip` + `sorted` 的 Stream 写法），并解释为什么要裁剪
   - 把实体 `Message` 按 `sender` 映射为 Spring AI 的 `UserMessage` / `AssistantMessage`
3. 编写测试接口 `TestAiController`，提供一个 **非流式** 的 `POST /test/ai/aggregate` 接口：调用你的实现后把所有 chunk 拼成完整回复一次性返回（用 `toStream()` 收集），方便无法联网时用 Mock 实现验证。

### 题目 3：SSE 流式对话接口 + 客户端对接（15 分）

**背景（对应本周 commit `6876c92`、`d0c5057`）：**
后端用 `SseEmitter` 把 AI 回复逐段推给前端；前端把 fetch 换成 axios 后，在响应拦截器里统一拆 `Result` 外壳。

**任务：**
1. 后端：编写 `SseDemoController`，提供 `GET /sse/demo?topic=xxx`，用 `SseEmitter` 推送事件：
   - 先推 1 个 `start` 事件（携带 topic）
   - 再逐个推送 `chunk` 事件（模拟 5 段文本，可用 `Thread.sleep` 模拟模型生成延迟）
   - 最后推 `final` 事件并 `complete()`
   - 要求：推送逻辑放到独立线程池中执行，**线程池线程必须设为 daemon**，并加注释说明为什么
2. 前端（或用 JS 单文件也行）：写一段浏览器端代码，用原生 `EventSource` 或 fetch-stream 消费上述 SSE 事件，把 chunk 追加渲染到页面上。
3. （附加 2 分，总分不超过 15）在 axios 响应拦截器中实现对 `Result` 外壳的统一拆包：`code !== 200` 时 reject，成功时直接返回 `data`。

### 可选主题

**① 为什么要做 Controller → Service → Repository 分层？**（本周 commit `74336a7` 把 100+ 行的 Controller 拆成了三层）
- 需要讲清：重构前后 Controller 的变化；每层职责边界；Repository 层挡在 Service 和 MyBatis-Plus 之间带来了什么好处（可换 ORM？可测试？）

**② MapStruct Converter 解决了什么问题？**（本项目 `converter/` 下有 8 个 Converter）
- 需要讲清：手写 BeanUtils 拷贝的坑；MapStruct 编译期生成代码的原理；为什么 Entity 与 DTO 要分开

**③ 为什么 ChatServiceImpl 的线程池要改成守护线程（daemon）？**（本周真实踩坑：SSE 流式请求卡住 → JVM 无法退出 → 端口 8080 残留占用 → 下次启动报错）

**④ SSE 流式响应 vs 普通 HTTP 同步响应**（本周用 `SseEmitter` + `Flux<String>` 实现了打字机效果）
- 需要讲清：为什么 AI 对话要用流式（首字延迟、体验）；SSE 与 WebSocket 的区别与取舍；`Flux` 到 `SseEmitter` 之间数据是怎么流动的

**⑤ 统一响应外壳 `Result` 的设计取舍**（本周 `06c1c95`：HTTP 状态码保持真实语义，code 字段与之一致）
- 需要讲清：为什么需要统一外壳；为什么 HTTP 状态码不统一改成 200 而保留 401/404/402（对比两种流派）；前端 axios 拦截器如何配合

**⑥ Spring AI 的 ChatClient 抽象与上下文窗口**（本周 `DeepseekAiServiceImpl` 中 `HISTORY_WINDOW = 10` 的设计）
- 需要讲清：ChatClient 的 prompt 组装流程（system / messages / user）；为什么历史不能无限带（token 上限与成本）；`skip + sorted` 裁剪的取舍（丢掉旧消息可能带来什么问题）
